Eigene Skills bauen: Workflows automatisieren

Advanced 📖 10 Min. Lesezeit Aktualisiert: Juni 2026
Video: Deinen ersten Skill erstellen

Was ist ein Skill?

Ein Skill ist ein wiederverwendbarer Workflow, den Claude Code mit einem Slash-Befehl aktiviert. Statt jedes Mal den gleichen Prompt zu schreiben, definierst du den Ablauf einmal als Skill — und kannst ihn danach jederzeit mit /mein-skill aufrufen.

Anatomie eines Skills

Jeder Skill ist ein Ordner unter .claude/skills/ mit mindestens einer SKILL.md Datei:

.claude/skills/mein-skill/
├── SKILL.md              # Pflicht: Skill-Definition
├── references/           # Optional: Referenz-Dokumente
│   ├── sop.md           # z.B. Standard Operating Procedure
│   └── templates.md     # z.B. Prompt-Templates
└── scripts/             # Optional: Python/Bash Scripts
    └── helper.py

Die SKILL.md Datei

Die SKILL.md ist das Herzstück. Sie sagt Claude Code wann der Skill aktiviert wird, was er tun soll und wie er arbeiten soll.

# Mein Skill Name

## Trigger
Dieser Skill wird aktiviert wenn der User "/mein-skill"
sagt oder "mach mir ein XYZ".

## Workflow
1. Frage den User nach [Input A] und [Input B]
2. Lese die Referenz-Datei references/sop.md
3. Erstelle [Output] basierend auf den Inputs
4. Speichere das Ergebnis in output/

## Regeln
- Immer deutschen Text verwenden
- Kosten vorab zeigen bei API-Aufrufen
- Output-Ordner nach Fertigstellung öffnen

Best Practices für SKILL.md

  • Klare Trigger definieren: Liste alle Phrasen auf, die den Skill aktivieren sollen
  • Workflow nummeriert: Schritte klar durchnummerieren, damit Claude Code den Ablauf versteht
  • Regeln explizit: Alles was IMMER gelten soll als Regel formulieren
  • Referenzen nutzen: Komplexe Informationen in references/ auslagern, nicht alles in die SKILL.md packen
  • Outputs definieren: Klar sagen wo und in welchem Format das Ergebnis landen soll

Referenz-Dateien

Der references/ Ordner enthält alles was Claude Code als Kontext braucht:

  • SOPs: Standard Operating Procedures — der "goldene Pfad" für den Workflow
  • Templates: Prompt-Templates, Text-Vorlagen, Formatierungsregeln
  • Beispiele: Gute Beispiel-Outputs als Referenz
  • Design-Regeln: CI-Farben, Fonts, Layout-Vorgaben

Tipp: Claude Code liest Referenz-Dateien automatisch wenn sie in der SKILL.md referenziert werden. Du musst sie nicht manuell laden. Nutze Formulierungen wie "Lese references/sop.md für die genauen Regeln".

Beispiel: Cold Mailing Skill

Ein konkretes Beispiel — ein Skill für automatisierte Cold-Mailing-Sequenzen:

# Cold Mailing Skill

## Trigger
/cold-mailing, "E-Mail Sequenz erstellen",
"Cold Outreach", "Mailing Kampagne"

## Workflow
1. Zielgruppe + Angebot vom User erfragen
2. references/email-frameworks.md lesen
3. 5-E-Mail-Sequenz generieren:
   - E-Mail 1: Cold Opener (Pain Point)
   - E-Mail 2: Value Add (Case Study)
   - E-Mail 3: Social Proof
   - E-Mail 4: Objection Handler
   - E-Mail 5: Break-Up Email
4. Betreffzeilen-Varianten (je 3 pro E-Mail)
5. Als Markdown-Datei speichern

## Regeln
- Deutsche Sprache, Sie-Form
- Keine Spam-Trigger-Wörter
- Jede E-Mail max. 150 Wörter
- Betreffzeilen max. 50 Zeichen

Skill testen und iterieren

Erstversion schreiben

Erstelle die SKILL.md mit dem grundlegenden Workflow. Halte es einfach — du kannst später erweitern.

Testen

Starte Claude Code neu und rufe /dein-skill auf. Prüfe ob der Workflow wie erwartet läuft.

Feedback einarbeiten

Wenn etwas nicht passt: "Merk dir, dass bei /mein-skill immer X gemacht werden soll" — Claude Code speichert das als Feedback-Memory.

SKILL.md anpassen

Regeln und Learnings aus dem Testen in die SKILL.md übernehmen, damit sie beim nächsten Mal direkt stimmen.

Häufige Fehler

  • Zu vage: "Erstelle guten Content" → Besser: "Erstelle 5 LinkedIn-Posts mit Hook-Opener, max. 300 Zeichen"
  • Keine Referenzen: Alles in die SKILL.md packen macht sie unübersichtlich. Nutze references/.
  • Fehlende Regeln: Wenn der Output immer leicht anders ist, fehlen klare Constraints.
  • Kein Output-Pfad: Ohne definierten Speicherort landen Dateien irgendwo.
