Eigene Skills bauen: Workflows automatisieren

Advanced 📖 10 Min. Lesezeit Aktualisiert: Juni 2026

Was ist ein Skill?

Ein Skill ist ein wiederverwendbarer Workflow, der über einen Slash-Befehl aktiviert wird. Statt Claude Code jedes Mal von Grund auf zu erklären, was er tun soll, definierst du den Ablauf einmal — und rufst ihn danach mit einem einzigen Befehl wie /cold-mailing oder /logo auf.

Skills sind der Kern der Heartbeat Content Engine. Sie machen den Unterschied zwischen "KI als Chatbot" und "KI als automatisiertes Produktionssystem".

Anatomie eines Skills

Jeder Skill lebt in einem eigenen Ordner unter .claude/skills/ und hat eine feste Struktur:

.claude/skills/mein-skill/
  SKILL.md            # Hauptdatei: Trigger, Workflow, Regeln
  references/         # SOPs, Templates, Beispiele
    template.md
    design-rules.md
    beispiel-output.md
  scripts/            # Optional: Python/JS Helper-Scripts
    generate.py

Wichtig: Die SKILL.md ist die einzige Datei, die Claude Code automatisch liest wenn der Skill getriggert wird. Alles in references/ muss in der SKILL.md explizit referenziert werden.

Die SKILL.md Datei

Die SKILL.md hat drei Kernbereiche: Trigger (wann wird der Skill aktiviert), Workflow (was passiert Schritt für Schritt) und Regeln (welche Constraints gelten).

# Mein Skill

## Trigger
Dieser Skill wird aktiviert wenn der User "/mein-skill" sagt
oder "erstelle mir XY" anfragt.

## Workflow
1. Kundendaten sammeln (Name, Branche, Zielgruppe)
2. Referenz-Datei lesen: references/template.md
3. Content nach Template generieren
4. Design-Regeln aus references/design-rules.md anwenden
5. Output in output/ Ordner speichern
6. Ordner im Finder öffnen

## Regeln
- IMMER echte Umlaute (ä, ö, ü) verwenden
- Maximal 3 Varianten pro Durchlauf
- Output-Format: PNG, 1080x1080px
- Kosten vorab anzeigen und Bestätigung einholen

Best Practices

  • Klare Trigger: Definiere exakt, welche Phrasen den Skill aktivieren sollen. Je eindeutiger, desto weniger Fehlauslösungen.
  • Nummerierter Workflow: Jeder Schritt bekommt eine Nummer. Claude Code arbeitet die Schritte sequentiell ab und überspringt nichts.
  • Explizite Regeln: Alles was immer gelten soll (Sprache, Format, Größe, Stil) gehört in die Regeln. Keine Annahmen.
  • References nutzen: Große Templates, Beispiele und SOPs in eigene Dateien auslagern statt alles in die SKILL.md zu packen.
  • Output definieren: Wo landen die Ergebnisse? Welches Format? Welcher Dateiname? Klar definieren.

Referenz-Dateien

Der references/ Ordner enthält alles, was der Skill als Kontext braucht:

TypZweckBeispiel
SOPsStandard Operating Procedures für den Workflowsop-ad-erstellung.md
TemplatesVorlagen für den generierten Outputemail-template.md
BeispieleKonkrete Beispiel-Outputs als Qualitätsreferenzbeispiel-output.md
Design-RegelnCI-Farben, Schriften, Layout-Constraintsdesign-rules.md

Beispiel: Cold Mailing Skill

Ein vollständiges Beispiel eines produktiven Skills:

# Cold Mailing Skill

## Trigger
Dieser Skill wird aktiviert wenn der User "/cold-mailing" sagt,
"E-Mail-Sequenz erstellen" oder "Cold Mails schreiben" anfragt.

## Workflow
1. Marketing Offer Framework abfragen:
   - Zielgruppe (Rolle, Branche, Unternehmensgröße)
   - Pain Point (konkret, messbar)
   - Angebot (Ergebnis, nicht Produkt)
   - Social Proof (Zahlen, Namen, Zeiträume)
   - Häufigster Einwand
   - Gewünschter CTA
2. Optional: Lead-Daten aus Close CRM abrufen (MCP)
3. Referenz lesen: references/email-templates.md
4. 5-E-Mail-Sequenz generieren:
   - E-Mail 1: Cold Opener (Problem benennen)
   - E-Mail 2: Value Add (Mehrwert liefern)
   - E-Mail 3: Social Proof (Ergebnisse zeigen)
   - E-Mail 4: Objection Handler (Einwand entkräften)
   - E-Mail 5: Break-Up (letzte Chance)
5. 3 Betreffzeilen-Varianten pro E-Mail (A/B/C)
6. Output als Markdown speichern

## Regeln
- Deutsche Sprache, Sie-Form
- Max. 150 Wörter pro E-Mail
- Max. 50 Zeichen pro Betreffzeile
- Keine Spam-Trigger-Wörter
- Ein CTA pro E-Mail
- Kein HTML, Plain-Text-Format

Testen und Iterieren

Ein Skill wird selten beim ersten Mal perfekt sein. Der Entwicklungsprozess ist iterativ:

SKILL.md schreiben

Starte mit einer ersten Version. Trigger, Workflow und die wichtigsten Regeln definieren.

Testen

Starte Claude Code neu und rufe /dein-skill auf. Prüfe ob der Workflow wie erwartet läuft.

Feedback einarbeiten

Wenn etwas nicht passt: "Merk dir, dass bei /mein-skill immer X gemacht werden soll" — Claude Code speichert das als Feedback-Memory.

SKILL.md anpassen

Regeln und Learnings aus dem Testen in die SKILL.md übernehmen, damit sie beim nächsten Mal direkt stimmen.

Häufige Fehler

  • Zu vage: "Erstelle guten Content" → Besser: "Erstelle 5 LinkedIn-Posts mit Hook-Opener, max. 300 Zeichen"
  • Keine Referenzen: Alles in die SKILL.md packen macht sie unübersichtlich. Nutze references/.
  • Fehlende Regeln: Wenn der Output immer leicht anders ist, fehlen klare Constraints.
  • Kein Output-Pfad: Ohne definierten Speicherort landen Dateien irgendwo.
